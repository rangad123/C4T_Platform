## Corrections to the first version of this review

Two verdicts in my first pass were wrong, and both have been re-checked
against the databases:

- I said per-tester **browser records** were never migrated. They were —
  5,469 rows. I had assumed it from the migration scope rather than counting.
- I said the **Argentina** problem was probably an ISO-code mapping gap. The
  real cause was worse and is now fixed: the migration read the wrong one of
  two country columns and dropped the country of 5,736 testers.

## Items in the raw list that are already resolved

Checked against the code and found **not reproducible** — likely fixed since the
sheet was written:

- **"Password field has no eye icon to show/hide"** (raised twice, sign-up and
  sign-up-with-client). A show/hide toggle exists on all four password surfaces:
  login, register, reset-password, and both profile pages.
- **"Admin → Users search shows 'No users match the filter' for an existing
  user"** (raised twice). Verified live against seven queries — partial name,
  full name, email, mixed case — all return matches.
- **"Organisation dropdown is not showing the available organisation list"** —
  this one was **real and is now fixed** (`0254ef7`). The select was capped at
  the API's 100-row page limit, so **176 of 276 organisations could not be
  selected at all** and the field gave no sign anything was missing. It now
  pages to exhaustion and sorts alphabetically. Verified live: 276 options.

## Items that are product decisions, not defects

- **"Contact number accepting more than 10 digits"** — the field allows up to 24
  characters deliberately, so international numbers with a country code and
  separators fit. Capping at 10 would break every non-Indian number. Confirm if
  you want an India-only rule.
- **"Sign-In UI is inconsistent — popup from landing page, full page after sign
  out"** — this is a deliberate intercepting route: an in-app navigation opens
  the modal, a direct load renders the full page. Worth aligning if you dislike
  it, but it is working as built.

## Not yet reviewed

### Two of them are testing-environment artefacts, not product defects

- **"Google Sign-Up fails as 127.0.0.1 refused to connect"** — checked
  production directly: `GOOGLE_REDIRECT_URI` is the live host, and
  `/api/v1/auth/google` returns a 302 to `accounts.google.com` carrying the
  correct production `redirect_uri`. A `127.0.0.1` callback can only come from
  a local dev environment.
- **"Sign-up page displays 'Could not reach the sign-up service'"** — the same
  signature: that message appears when the web app cannot reach the API, which
  in local development means the API process on port 4000 is not running.

Both were almost certainly raised while testing against a local checkout rather
than the deployed site. **Worth confirming which environment the sheet was
written against** — if it was local, a number of the landing-page and sign-up
rows may not reflect production at all, and re-testing against
`https://13.235.96.108.sslip.io` would clear several rows at once.

### One mapping decision worth your review

The legacy `org_desc` (organisation description, populated on all 276) is
migrated into `Organisation.notes`, which the schema describes as *internal
admin notes*. If that text was customer-facing in the old portal, it is now
hidden from the customer. Say the word and it can be surfaced or moved.

### Why no organisation has a logo

`org_image` is empty on all 276 legacy rows — no organisation ever uploaded
one. The blank company logos are not a migration failure. (Project logos are a
different field and 255 of them migrated fine.)

### A crash found next to the progress bug

Not on your sheet, but worth knowing: reopening a completed project wrote
`progressPercent: null` to a NOT NULL column, and typechecked only because the
update object was cast to `ProjectUncheckedUpdateInput`. Every project on the
platform is COMPLETED and `COMPLETED → IN_PROGRESS` is the only move that
status has — so this sat on the path of the only status change available
anywhere. Fixed, and the cast is gone.
