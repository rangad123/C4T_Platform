# Explain in place, AI transparency, vocabulary and honest numbers (UX-D)

What changed for the tester, why, and what is not covered. The audit behind it is `.scratch/ux/AUDIT.md`; the vocabulary table is in `.scratch/briefs/COMMON15.md`. Only the UI words change: API enums, database values, routes and the technical sections of the docs keep their names.

## What the tester sees

**One vocabulary.** A test is *Passing*, *Needs a look* (only for findings such as a missing security header, an accessibility problem or a visual change), *Failing* or *Not run yet*. Creating tests starts with an *exploration*; running tests is a *run* (*Running tests*, *Run finished*, *Exploration failed*). The thing that runs tests on your own computer is a *runner*; "runner agent" appears only in the install command. Other words: *Shared elements* (the "Objects" tab, "Make shared" is now *Use as shared element*), *Reusable steps*, *Code test* with the action *Switch to code* (was "hand-written" and "take over"), *Run sequence* (was runbook), *test idea* (was scenario). Status badges are sentence case; mono is for ids, times and code. The test id is grey meta after the type, priority and kind, never the lead.

**A word you may not know explains itself.** `<Term word="…">` (in `web/src/components/ui.tsx`, sentences in `GLOSSARY` in `web/src/lib/labels.ts`) is a text button with a dotted underline. Press it or hit Enter and a one-sentence note opens in place; it stays open, Escape or a press elsewhere closes it, nothing is hover-only. Used for *finding*, *repair*, *auto-fix*, *trace*, *control*, *shared element*, and available for *runner*, *quarantine*, *run sequence*, *reusable steps*, *code test*.

**Where a test came from** (`web/src/features/provenance/`). One line under the title built only from what the test answer stores: what made it (exploration, OpenAPI document, recording, description, import, Git, code, the check that created it), the endpoint or journey and start page when stored, the model name when stored, and the date of its first script. **Why this test?** appears only when the test stored a sentence: the idea behind it, the AI's note, the requirements it covers, and how it is rated. Nothing is guessed: no "what the AI saw" unless the test kept it.

**Auto-fix.** A test that passed only after more than one attempt says *Auto-fixed during creation: it passed on attempt N* and lists the attempts that did not pass with their reasons. Limit: the platform stores each attempt's result, not the earlier version of the steps, so there is **no step-by-step diff** of what the auto-fix changed. `attempts` also counts a straight re-run (scheduled runs retry a failure once), so the wording says "attempt", not "correction".

**What failed** (`web/src/features/evidence/FailureSummary.tsx`). Replaces the generic failure text: the failed step in plain words (from the spec step, not the runner's title), **Expected** and **Got** from the platform's `expected`/`actual` fields when present (otherwise "The run said: …" with the stored message, cleaned), links to the screenshot, recording and trace that still exist, the named cause when the platform names one (`failure.kind` `missing-api-token`: "No API token is saved for this project" with an *Add an API token* link), and **What you can do**: *Add an API token*, *Apply the repair* (scrolls to the repair card; only when one can be applied), *Edit steps*, *Switch to code* (or *Edit the code* for a code test), *Quarantine* (only when the test is eligible) and *Run again*. Only actions that exist on the page are offered. The stale advice "edit it and import it again" is gone. For a finding the heading is *What was found*, the status callout says *This test found something that needs a look* and one sentence says it is a finding, not a broken test.

**The script shows the test first** (`web/src/components/ScriptPreview.tsx`, `web/src/lib/script.ts`). The generators write the platform's code (evidence recorder, test values, hooks, the sign-in origin check) before the test and put no marker between them. Adding a marker would change every pinned script, so the preview finds the body instead: the first line that starts with `test(`, `test.describe(` or the per-row `for` loop of a data-driven test. The setup above it is folded behind **Show setup code (N lines)**. Copy and Download give the whole script. A script with no such line, or a preamble under 8 lines, is shown whole. Used on the test page and in the steps editor's script preview.

**Repair applied, and Undo** (`web/src/features/healing/HealingSuggestion.tsx`). After *Apply and run again* the card becomes *Repair applied*: "the “Add to cart” button is now found as the “Add to basket” button", *See what changed* (before and now) and **Undo this repair**. Undo reads the test's steps through the steps editor's route, puts the old locator back in that one step and saves it (a new version in the test's history, the script made again, the test run again). It is offered only while the step still has the repaired locator, so it never undoes a later edit. A repair of a **shared element** changed other tests too: there is no one-press undo; the card says what the element was and links to *Shared elements*. The card shows for web tests that are not code tests, passing or not, so the applied state is visible after the test passes.

**Less noise.** Controls ("Relevant controls") move behind a **Compliance** line that says why, and only on security and accessibility tests (other tests: the platform maps some controls to everything, which says nothing; the Compliance tab has the project view). With no issue tracker connected the failing test shows one line and one link instead of a card. The Overview's "What we remember about this site" card appears only once something is remembered (the confirmation after *Forget* still shows).

**The AI is named where it acts.** *Write a test* says "Uses the AI model. It decides each step from what it sees on the page, then saves the test and runs it". The exploration form says it uses the AI model and that API-only tests do not. The glossary explains *auto-fix*. Repair suggestions are deterministic and say nothing about a model. No confirmation dialogs were added for harmless reads.

**Honest numbers.** The dashboard row and the release page show the platform's pass-rate sentence (`latestRun.sentence` and `.others`: "2 of 3 tests that ran passed, 1 could not be validated") and never a bare percentage next to a contradicting count; ribbons and legends read *passing / need a look / failing / not run yet*. The release page no longer says "Release Release 1.4" when the release is named "Release …". The runner card shows the platform's phone sentence (`phones.text`) under the badges, so it agrees with the agent card (`capabilities.android.summary`). The platform's own prose about "analysis" (readiness reasons, "Since the last analysis") is reworded on screen by `plainWords()` in `labels.ts`; the answers are unchanged.

## Decisions

- Status words come from one table (`VALIDATION` in `labels.ts`); every badge, chip, ribbon label and callout uses it.
- "Needs a look" is reserved for findings. A finding stays a finding on every run path (platform fix by UXP); the UI never re-labels it.
- The compliance disclosure rule is by test type (security, accessibility) and by origin (security, accessibility and access checks). It is a UI rule, not a platform fact.
- Undo uses the existing version history instead of a new storage: the previous locator is in the stored proposal.

## Not covered

- The tab strip (`ProjectTabs`) now says *Shared elements*; the rest of the navigation, the Tests-page toolbar and the run strip belong to the navigation and run-control work.
- "Cancel analysis" and other cancel wording on the progress card are the run-control builder's; `friendlyError("Cancelled")` still says "This analysis was cancelled".
- Platform error messages that name the old actions ("Edit the script" in API errors, "Analyze again, Advanced options" in the missing-token reason) are unchanged. So are the platform's sentences "could not be validated" in the pass-rate text.
- No diff of what an auto-fix changed (not stored), no screenshot of what the AI saw while exploring (not stored), no created-by name for recordings.
- The compliance disclosure is hidden on tests where the mapping is generic; there is no per-test measure of how informative a mapping is.
- Wording in other languages, and the PDF/HTML report printouts, were not changed.
